# packages/shared（契約）

全 app が参照する唯一の定義。ここの変更は全体に影響する。

## このパッケージに置くもの

- エンティティの zod スキーマと、そこから導出した型（`z.infer`）
- 注文・注文明細・アーカイブのステータス列挙
- 状態遷移表（「現在の状態 → 次の状態 → 実行できる役割」をデータとして定義）
- API のリクエスト・レスポンスのスキーマ
- SSE イベントの型（判別可能なユニオン型）
- 識別子（注文ID・注文番号・確認コード）の形式

## 構成

| パス | 内容 |
| --- | --- |
| `src/ids.ts` | ID（ULID）、注文番号とその表示、確認コード（紛らわしい文字を除いた 4 文字）、匿名トークン |
| `src/primitives.ts` | 日時・日付・金額（円の整数）・データ置き場からの相対パス |
| `src/status.ts` | 各ステータスの列挙と、画面に出す表示名（`orderStatusLabels` など） |
| `src/transitions.ts` | 状態遷移表（注文・明細・印刷シート・アーカイブ）。データだけ |
| `src/entities/` | エンティティ。DB の 1 行に対応する形（明細を含まない注文など） |
| `src/api/` | 画面向けの入出力（`OrderView` など）と、全エンドポイントの一覧（`endpoints.ts`） |
| `src/errors.ts` | エラーの種類（`ErrorCode`）、HTTP ステータス、失敗時の本体 |
| `src/sse.ts` | SSE イベント。購読の種類ごとに流してよいものを分けている |

使うときは `import { ... } from "@canbadge/shared"` だけにする（深いパスを直接 import しない）。

## ルール

- ランタイムの依存は zod のみ。DB・フレームワーク・Node/Bun 固有 API に依存しない（ブラウザからも読み込まれるため）
- 遷移表は関数ではなくデータで表す。検証ロジックは `packages/db` が持つ
- 既存フィールドの削除・型変更・ステータスの削除は破壊的変更。行う場合は影響する app を列挙して PR に書く
- フィールドの追加は、既存の利用側が壊れないよう optional で追加するのを基本とする
- 変更後は必ずリポジトリ全体で `bun run typecheck` を実行し、影響範囲を確認する
- エンドポイントを追加・変更するときは、`src/api/endpoints.ts` の一覧と、入出力のスキーマを一緒に直す。一覧のテスト（`endpoints.test.ts`）が、パスの重複・認証の種類・パスの引数の食い違いを検出する
- 画面に返す形（`*View`）に、秘密（匿名トークン、スタッフ画面への確認コード、呼び出しモニターへの注文 ID）を含めない。含めていないことは `schemas.test.ts` で確かめている
