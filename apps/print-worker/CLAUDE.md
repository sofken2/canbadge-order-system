# apps/print-worker（面付け・印刷）

印刷待ちの明細を用紙単位にまとめ、PDF を生成して印刷する。本番は Windows + Canon PIXUS TS6730。

## 構成

| パス | 内容 |
| --- | --- |
| `src/index.ts` | 起動。DB を開き、ドライバーを選び、印刷キューの巡回を始める |
| `src/queue.ts` | 印刷キュー（P02）。`runQueueOnce`（1 回の巡回）と `startQueueLoop`（止めるとき、動いている巡回の終わりを待つ）。載せられないバッジを外す記録（`SkipRegistry`） |
| `src/plan.ts` | 次のシートの組み立て。どのバッジを何個載せるか、いま印刷するか待つかを決める純粋な計算 |
| `src/recovery.ts` | 起動時に、印刷中のまま残っているシートを知らせる（自動では、印刷し直さない） |
| `src/driver.ts` | 印刷ドライバー（`PrintDriver`）の型と、環境変数からの選択（`createDriver`）。開発用は PDF を `data/print-out/` に複製する |
| `src/driver-sumatra.ts` | 本番用ドライバー（P03）。SumatraPDF を、拡大縮小なしで呼ぶ。引数の組み立て・場所の検索・プリンターの一覧・起動時の確認 |
| `src/printers-cli.ts` | `bun run printers`：Windows のプリンター名の一覧（`PRINTER_NAME` に書く名前を調べる） |
| `src/layout.ts` | 用紙の上の配置（面付け）。mm・用紙の左上が原点。`layoutSlots`（位置の計算）・`calibrate`（較正の変換）。画面を持たない純粋な計算 |
| `src/sheet-pdf.ts` | `renderSheetPdf(spec, badges, { dataDir, … })`。バッジの画像を、実寸で円に切り取って並べ、円の下に注文番号を印字した PDF（1 ページ） |
| `src/calibration-pdf.ts` | `renderCalibrationPdf(spec, { applyCalibration })`。実機で測る、較正用ページ（P03 で使う） |
| `src/pdf-draw.ts` | PDF に描く小さな道具。mm（用紙の左上が原点）から、PDF の座標（pt・左下が原点）への変換は、ここだけで行う |
| `src/calibration-cli.ts` | `bun run calibration` で、較正用ページを `data/print-out/` に書き出す |

## 印刷シートの PDF（P01）

- **用紙は A4（`badgeSpec.paper`）。バッジの印刷円（見える円 58mm + 塗り足し 6mm × 2 = 70mm）を、2 列 × 3 行で並べる**。全体は、印刷できる範囲の中央
- **並び順は、左上から、右へ、次の行へ。** `position` がこの順で、スタッフ画面の「印刷」の履歴の並びと同じ。用紙の何番目かも、円の下の左に、小さく印字する
- 各バッジの画像（エディタが出す、塗り足しまでの正方形の PNG）は、**印刷円の中だけに切り取って**置く。円の縁に、細い灰色の線（切り抜きの目安）を引く。縁は、缶の裏に折り込まれる部分なので、仕上がりの表には出ない
- キラフィルムを貼るバッジ（明細の `kiraQuantity` 個ぶん。個数のうち先頭から）は、注文番号の横に `007 KIRA` と印字する。組み立てで貼り忘れないための目印（`labelText`）
- 注文番号は円の真下。用紙の左上に、シートの名前と日時（日本時間の「分」まで）を小さく印字する。「印刷」の履歴の「20:40 に印刷」と見比べられる
- 寸法は、画像の画素数に関係なく、mm から pt へ換算して配置する（実寸）。画像が正方形でなければ、円を覆うように拡大して中央を使う
- **標準フォントは日本語を描けない**ので、PDF の文字は ASCII だけ（注文番号は数字）
- **較正**：`badgeSpec.calibration`（倍率・ずらし）を、シート全体に掛ける。補正なし（倍率 1・ずらしなし）のときは、何も掛けない。`calibrate` の意味：用紙の左上を原点に、x' = x × scaleX + offsetX、y' = y × scaleY + offsetY（y は下向き。offset が正なら、右・下）
- **較正用ページ**：`bun run calibration`（補正なし。測定用）／`bun run calibration --applied`（補正あり。確認用）。入れ子の枠（縁から 1〜10mm）で、プリンターの印刷できない縁を、定規（横 160mm・縦 260mm）で、倍率を、円で、大きさを測る。**必ず「実際のサイズ（100%）」で印刷する**
- 画像が読めない（ない・PNG/JPEG でない・データ置き場の外を指す）ときは、PDF を作らず、キューは `failed` を返す（シートは記録されず、バッジは印刷待ちのまま）。**問題のバッジを避けて次へ進む処理は P02**

## 印刷キューの制御（P02）

- **載せるバッジの選び方**：再印刷のバッジが先、次に支払いの早い順（db の `listPrintableItems`）。先頭から、残りの枠に収まるバッジを載せる
- **個数のあるバッジ**：個数の分だけ枠を使い、用紙に同じバッジを並べる（`copies`）。db の位置（`position`）は、そのバッジの**最初の 1 個**の用紙の位置（例：個数 2 のバッジと、1 個のバッジなら、位置は 0 と 2）。1 つのバッジは、複数のシートに分けない。**残りの枠に収まらないバッジは、載せずに次のシートに回し**、後ろの収まるバッジを載せる（回されたバッジは、次のシートの先頭になる）
- **いつ印刷するか**：枠がすべて埋まったら、すぐ。埋まらなくても、載せるバッジのどれかが、待ち時間に達したら、そのときの分で。待ち時間は、ふつうのバッジが `printMaxWaitSeconds`（既定 60 秒）、**再印刷のバッジは、その半分（30 秒。`REPRINT_WAIT_RATIO`）**
- **再印刷と、印刷待ちのバッジの、いっしょの印刷**：再印刷が先に載り、残りの枠に、そろっている印刷待ちのバッジが、一緒に載る。再印刷が 1 個だけのときは、ほぼ空の用紙を、すぐ出さず、半分の時間だけ、ほかのバッジを待つ（お客さんは、やり直しを待っているので、長くは待たせない）。再印刷の待ち時間は、**再印刷に戻ったとき**から数える（支払いの時刻から数えると、すぐ印刷してしまうため）。印刷待ちに戻った時刻は、DB にないので、このワーカーが、初めて見た時刻で、代わりにする（ワーカーを再起動すると、数え直し）
- **緊急印刷**：スタッフ画面の「緊急印刷」は、操作ログに `print_queue.flush` を残す（`requestPrintFlush`。印刷を止めているときは断る）。ワーカーは、**起動したあとの**依頼だけを見て（`createFlushWatcher`）、待ち時間を 0 にして巡回し、印刷待ちが空になる（または失敗・停止）まで続ける。用紙は埋まらなくても出る
- **一時停止中**は、新しいシートを作らない。再開すると、待ち時間の長いバッジは、すぐ印刷される
- **印刷の確認の操作はない。** ドライバーが成功したら、すぐ `completePrintSheet`（バッジは印刷済み・シートは確認済み・全バッジが印刷済みの注文は、自動で組み立て中）。用紙の不良は、組み立ての担当が、スタッフ画面の「印刷」の履歴から、バッジごとに再印刷する
- **ドライバーが失敗したら**、`failPrintSheet`（バッジは印刷待ちに戻り、シートは失敗）にして、**印刷を一時停止する**（止めないと、プリンターが直るまで、巡回のたびに、同じシートを作って、失敗し続ける）。プリンターを直したら、スタッフ画面の「印刷」で再開する
- **同時に印刷中にできるのは 1 枚。** いまのシートの印刷（ドライバーへの送信）が終わるまで、次を作らない。**db（`createPrintSheet`）が、同じトランザクションで保証する**ので、worker が 2 つ動いても、シートは 1 枚だけ
- **二重に印刷しない**：シートとバッジの状態を、印刷する**前に** DB に記録する。印刷の途中で落ちたときも、**自動では、印刷し直さない**（用紙がもう出ていたら、二重になるため）。印刷中のまま残ったシートは、再起動したとき、`recovery.ts`（`recoverOnStartup`）が、**印刷済みとして扱い**（注文は組み立て中）、ログで知らせる。用紙が出ていなかったバッジは、履歴から、バッジごとに再印刷する
- **載せられないバッジは、外して、ほかのバッジの印刷を止めない。** 画像がない・PNG/JPEG でない・壊れている・個数が 1 枚に載る数を超える、のどれか。載せる前に、画像を実際に読んで確かめる。外したバッジは**印刷待ちのまま**で、操作ログ（`print.skip`）とログ出力に、理由を残す。同じバッジは、15 分たつまで、確かめ直さない（画像が直されたら、そのあと、載る）
- 止めるとき（SIGINT・SIGTERM）は、動いている巡回が終わるのを待ってから、DB を閉じる

## 本番用ドライバー（P03）

- `PRINT_DRIVER=sumatra`、`PRINTER_NAME`（Windows のプリンター名。`bun run printers` で調べる）、`SUMATRA_PATH`（省略すると、`%LOCALAPPDATA%\SumatraPDF`・Program Files を探す）。**Windows だけ**
- 呼び出し：`SumatraPDF.exe -print-to "<プリンター名>" -print-settings "noscale,color,paper=A4" -silent "<PDF>"`。**`noscale` が、実寸で印刷するための、いちばん大事な指定**（拡大縮小しない）。`-silent` は、エラーの画面を出さない（無人で動くため）。用紙は、badge-spec の用紙の大きさから決まる
- 引数は配列で渡す（シェルを通さない）。プリンター名のスペース・引用符・記号は、そのまま 1 つの引数になる
- **成功は「印刷のジョブを、プリンターに送れた（終了コード 0）」こと。用紙が実際に出たかは、わからない。** 失敗（終了コードが 0 でない・60 秒たっても終わらない・起動できない）は、例外になり、キューは `driver-failed` を返す
- **失敗しても、自動では再試行しない**（失敗し続けないよう、印刷を一時停止する）。印刷係が、プリンターを直して、スタッフ画面の「印刷」で再開する
- 起動時に、プリンターが Windows に登録されているかを確かめ、なければ、登録されているプリンターの一覧つきで、ログに出す（止めはしない。プリンターが、あとで使えるようになることもある）
- **印刷の品質・用紙の種類・フチなし／あり・両面などは、Windows のプリンターの「印刷設定」の既定値で決まる**（`infra/processing-pc.md` の「プリンターの設定」）
- `bun run calibration --print`：較正用ページを書き出して、**実際に印刷する**（用紙が 1 枚出る）。実機の最初の確認に使う

環境変数：`PRINT_DRIVER`（`dev` か `sumatra`。既定 dev）、`PRINT_POLL_MS`（巡回の間隔）、`PRINT_WAIT_OVERRIDE_SECONDS`（印刷待ちの最大時間を、設定の代わりに上書きする。開発用）。

## ルール

- 印刷処理はドライバーのインターフェースで抽象化する
  - 開発用ドライバー: PDF を出力フォルダに書き出すだけ（全OSで動く。CI・テストはこちらを使う）
  - 本番用ドライバー: SumatraPDF を `-print-to "<プリンター名>" -print-settings "noscale"` で呼び出す（Windows のみ）
- 使うドライバーとプリンター名は環境変数で切り替える。コードに直書きしない
- 寸法は `packages/badge-spec` の mm 値から配置する。画像の解像度に関係なく実寸になるようにする
- 各バッジの横に注文番号を印字する
- 印刷中のシートは同時に1枚まで。印刷係の確認が済むまで次を送らない
- 印刷を実行する前に、シートと明細の状態を DB に記録する（再起動時の二重印刷を防ぐ）
- 状態の変更は `packages/db` の遷移関数を使う。SQLite の status を直接更新しない
- 外部コマンドの呼び出しは引数を配列で渡す（シェル経由の文字列連結をしない）
